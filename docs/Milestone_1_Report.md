## 1. Executive Summary & Educational Disclaimer

### 1.1 Project Overview
CampusTech 2026 is an SEO-optimized, highly accessible event website designed to centralize critical information for a fictional 36-hour national college technology hackathon. In modern university ecosystems, hackathon details are routinely fragmented across ephemeral social media flyers, third-party forms, chat channels, and campus noticeboards. Consequently, prospective student participants encounter high friction when attempting to find basic information regarding eligibility, team size limits, submission deadlines, problem tracks, schedules, and venue directions through organic search.

CampusTech 2026 solves this information fragmentation by implementing an 8-page crawlable, mobile-responsive, semantic web platform strictly aligned with Google's Search Essentials, Core Web Vitals, and Schema.org structured data standards.

### 1.2 Academic Prototype Disclaimer
This website is an educational mock prototype developed solely for academic coursework and demonstration at Bennett University under the supervision of Dr. Saumitra. All event dates, prize pools, and registration workflows are simulated in client state. No actual registrations, commercial solicitations, or financial transactions are conducted.

## 3. Member 2: Information Architecture & On-Page SEO (Nitin Jhajharia)

### 3.1 8-Page Information Architecture & Content Strategy
To provide maximum clarity and avoid content cannibalization, the site is divided into 8 cleanly differentiated pages, each serving a unique stage of the user journey:

1. **Home (`index.html`):** Broad event positioning, hero countdown, high-level highlights, social proof, and immediate calls-to-action.
2. **Overview (`overview.html`):** Mission, 36-hour sprint philosophy, participant journey, and core organizational pillars.
3. **Schedule (`schedule.html`):** Chronological 36-hour timeline across Day 1, Day 2, and Day 3 with interactive day-by-day tab filtering.
4. **Eligibility & Rules (`eligibility.html`):** Exact participation qualifications, team size limits (2–4), code of conduct, IP ownership, and grounds for disqualification.
5. **Registration (`registration.html`):** 3-step walkthrough, countdown deadlines, and an interactive prototype registration form.
6. **Challenges & Tracks (`challenges.html`):** Detailed breakdown of 5 innovation tracks (AI/ML, Web3, FinTech, HealthTech, Open Innovation) and 100-point judging rubric.
7. **Venue & Travel (`venue.html`):** Campus geographic coordinates, transport routes (Metro, Train, Air), on-campus amenities, and organizer contacts.
8. **FAQs & Past Editions (`faq.html`):** Interactive accordion resolving top friction queries, retrospective data from 2025, and student testimonials.

## 4. Member 3: Website Prototype & Technical SEO (Dipanshu Singh)

### 4.1 Frontend Architecture & Mobile Responsiveness
The website is engineered using vanilla semantic HTML5, modern CSS3 (Custom Properties, Flexbox, CSS Grid), and lightweight vanilla JavaScript. This architecture eliminates runtime framework overhead, resulting in instantaneous page loads (< 400ms) on mobile 3G/4G networks.

Key technical implementation details:
* **Mobile Viewport Optimization:** Every page implements `<meta name="viewport" content="width=device-width, initial-scale=1.0">`.
* **Accessible Contrast:** Colors adhere to WCAG 2.1 AA standards (minimum 4.5:1 contrast for normal body text and 3:1 for large headings).
* **Responsive Navigation Drawer:** Hamburger navigation on mobile devices with `aria-expanded` attributes.
* **Breadcrumb Hierarchy:** Contextual `<ol class="breadcrumbs">` elements embedded across all subpages, reinforced with `schema.org/BreadcrumbList` microdata.

### 4.2 Search Engine Indexing Controls (`robots.txt` & `sitemap.xml`)
* **`robots.txt`:** Directs web crawlers to index all public informational pages while explicitly pointing to the XML sitemap.
* **`sitemap.xml`:** Validated XML protocol containing all 8 canonical URLs, timestamps (`lastmod`), change frequencies, and indexation priority levels (1.0 for Home, 0.9 for Schedule and Registration, 0.8 for Overview/Eligibility/Challenges, 0.7 for Venue/FAQs).

### 4.3 Structured Data Implementations (JSON-LD)
Structured data is implemented using JSON-LD scripts embedded in the `<head>` of relevant documents:
1. **`schema.org/Hackathon` & `Event` (on `index.html`):** Declares start date (`2026-11-14`), end date (`2026-11-15`), eventAttendanceMode, physical address (Bennett University), organizer entity, and free admission offer.
2. **`schema.org/FAQPage` (on `faq.html`):** Encodes top questions and accepted answers directly into Google's rich result format.
3. **`schema.org/BreadcrumbList` (on interior pages):** Provides nested positional indexing for search snippet path displays.
4. **`schema.org/Organization` (in footer):** Declares publisher identity, course alignment, and institutional location.

### 4.4 Technical Hosting Constraints & Mitigations (GitHub Pages)
| Hosting Constraint | Impact on SEO | Architectural Mitigation |
| :--- | :--- | :--- |
| No Server `.htaccess` / Nginx config | Cannot define custom server response headers (e.g. `X-Robots-Tag`, custom cache-control headers). | Managed via HTML `<meta>` tags (`robots`, `http-equiv`) and standardized `<link rel="canonical">` tags. |
| URL routing limitations | Cannot easily rewrite `.html` extension without subfolder routing. | Implemented clean relative internal links and standardized full canonical declarations for search engine consolidation. |
| Static CDN environment | No backend server to process database registration transactions. | Clearly designated as an educational prototype; client-side JS simulates submission with zero security risk. |
